# Proxy

# Техническое задание

## 1. Цель

Реализовать корпоративное решение, обеспечивающее:

* полный запрет локальных загрузок файлов на пользовательские устройства;
* возможность сохранения файлов **только на изолированный сервер**;
* проверку файлов антивирусом до доступа пользователя;
* последующий контролируемый экспорт файлов во внутреннюю корпоративную сеть;
* работу с **неподконтрольными внешними веб-ресурсами**;
* поддержку **Windows и Android** (iOS/macOS не входят в область работ).

Решение разрабатывается по требованию службы информационной безопасности и не предполагает скрытых механизмов.

---

## 2. Область применения

* Корпоративные устройства под управлением:

  * Windows 10/11
  * Android (Android Enterprise: Work Profile или Fully Managed)
* Браузер: Brave (Chromium-based)
* Сетевой доступ пользователей к интернет-ресурсам

---

## 3. Основные требования

### 3.1 Функциональные требования

1. Запрет локального скачивания файлов из браузера.
2. Перехват файлов, загружаемых по HTTP и HTTPS.
3. Сохранение перехваченных файлов на сервере в карантинном хранилище.
4. Проверка файлов антивирусным ПО.
5. Предоставление пользователю доступа к файлам через веб-портал.
6. Возможность экспорта проверенных файлов во внутреннюю корпоративную сеть.
7. Привязка файлов к пользователю (учётка на стороне сервера).

### 3.2 Нефункциональные требования

* Универсальность для всех внешних сайтов без изменения их кода.
* Отсутствие VDI / RBI / удалённых браузеров.
* Использование одного серверного узла средней производительности.
* Масштабируемость по количеству пользователей.
* Централизованное управление через MDM.
* Аудит и журналирование всех операций.

---

## 4. Архитектура решения

### 4.1 Компоненты

1. **Клиентские устройства**

   * Brave Browser
   * MDM (Intune / Android Enterprise)

2. **Сервер** (единый узел)

   * Forward Proxy с TLS inspection
   * Антивирус (через ICAP или встроенный)
   * Карантинное файловое хранилище
   * Веб-портал доступа пользователей

3. **PKI-инфраструктура**

   * Корпоративный Root CA для TLS inspection

---

## 5. Требования к клиентским устройствам

### 5.1 Brave Browser

* Применение корпоративных политик:

  * `DownloadRestrictions = 3` (запрет всех загрузок)
  * Запрет неуправляемых расширений
  * Запрет пользовательских профилей

### 5.2 Windows

* Установка корпоративного Root CA в хранилище доверенных корневых сертификатов компьютера.
* Принудительная настройка прокси/PAC через MDM или GPO.
* Блокировка QUIC (UDP/443).

### 5.3 Android

* Использование Android Enterprise.
* Установка корпоративного Root CA через MDM.
* Включение:

  * Always-on VPN
  * Block connections without VPN

---

## 6. Требования к серверу

### 6.1 Proxy / TLS inspection

* Поддержка HTTPS interception (MITM).
* Генерация подменных сертификатов сайтов, подписанных корпоративным Root CA.
* Возможность селективного TLS inspection (по доменам, категориям).

### 6.2 Обработка загрузок

После расшифровки TLS сервер должен:

1. Определять файловые ответы по:

   * Content-Disposition
   * MIME-типам
   * сигнатурам файлов
   * размеру ответа
2. Блокировать доставку файла клиенту.
3. Сохранять файл в карантин.
4. Запускать антивирусную проверку.

### 6.3 Антивирусная проверка

* Проверка каждого файла до предоставления доступа.
* Поддержка синхронного или асинхронного режима.
* Хранение результата проверки.

---

## 7. Веб-портал

Функциональность портала:

* Аутентификация пользователей (AD / LDAP / OIDC).
* Отображение списка файлов пользователя.
* Статусы: на проверке / чисто / заражено / заблокировано.
* Просмотр файлов (PDF, Office, изображения) без скачивания.
* Экспорт файлов во внутренние корпоративные ресурсы после разрешения.

---

## 8. Политики безопасности

* Исключения из TLS inspection:

  * банковские сайты
  * государственные порталы
  * ресурсы с certificate pinning
* Ограничения:

  * максимальный размер файла
  * допустимые типы файлов
* Хранение логов:

  * пользователь
  * источник
  * хэш файла
  * результат проверки

---

## 9. Ограничения и допущения

* HTTPS-перехват невозможен без доверия корпоративному Root CA.
* Некоторые мобильные приложения могут не работать с TLS inspection (вне браузера).
* Решение не гарантирует перехват трафика, идущего в обход VPN/прокси.

---

## 10. Критерии приёмки

1. Локальное скачивание файлов невозможно.
2. Файлы с HTTP и HTTPS сохраняются на сервере.
3. Пользователь не получает файл напрямую.
4. Файл доступен в портале после проверки.
5. Работает на Windows и Android.
6. Ведётся аудит всех операций.

---

## 11. Результат

Решение обеспечивает централизованный, контролируемый и безопасный механизм обработки файлов из внешних источников без использования VDI и без изменения сторонних информационных систем.
